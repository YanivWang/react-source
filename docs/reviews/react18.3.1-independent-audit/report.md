### F01 · P1 · bailout 子树会重复提交已经完成的 Effect

- **触发**：同一个稳定 Element 连续 `root.render` 两次；或 memo 子树不变，只更新兄弟文本。Effect 的依赖均为 `[]`。
- **官方 / 本地**：官方第一次 mount 后保持不变；本地第二次额外执行 layout cleanup/mount 与 passive cleanup/mount。memo 例官方日志 `["mount"]`，本地 `["mount","cleanup","mount"]`。
- **本地位置**：[ReactFiberCompleteWork.ts:131](/Users/wangcheng/Documents/workSpace/frontEnd/referenceProjects/repos/react/react-source/packages/react-reconciler/src/ReactFiberCompleteWork.ts:131)，尤其 146–147 行；[ReactFiberFlags.ts:41](/Users/wangcheng/Documents/workSpace/frontEnd/referenceProjects/repos/react/react-source/packages/react-reconciler/src/ReactFiberFlags.ts:41)。
- **官方对应**：[官方 ReactFiberCompleteWork.old.js:642](https://github.com/facebook/react/blob/v18.3.1/packages/react-reconciler/src/ReactFiberCompleteWork.old.js#L642) `bubbleProperties`；bailout 分支在 742–743 行只汇总 `StaticMask`。
- **根因**：本地计算了 `didBailout`，却不据此改变动态 flags 的汇总，直接把复用 child 上一次的动态 Effect 标志带入新 commit。`StaticMask` 也只实现 RefStatic，没有完整静态 Effect 协议。
- **影响与证据**：订阅、layout 测量和只执行一次的初始化无故断开/重建，直接破坏 bailout 与 commit 不变量。`stable-element-effects`、`memo-subtree-effects` 两种不同触发均复现。修复应恢复静态/动态标志与 bailout 的配套语义，不宜只在某个 Effect 分支加特判。

### F02 · P1 · 已完成子树在时间片间收到的新更新丢失

- **触发**：Transition 正在渲染后面的慢兄弟；前面的 memo Panel/Counter 已完成；在让出窗口对 Counter 再发 Transition 更新。
- **官方 / 本地**：两者都确认 `interrupted: true`。官方最终 Counter 为 `"1"`，本地为 `"0"`。
- **本地位置**：[ReactFiberConcurrentUpdates.ts:30](/Users/wangcheng/Documents/workSpace/frontEnd/referenceProjects/repos/react/react-source/packages/react-reconciler/src/ReactFiberConcurrentUpdates.ts:30) `enqueueUpdate`、[ReactFiberConcurrentUpdates.ts:78](/Users/wangcheng/Documents/workSpace/frontEnd/referenceProjects/repos/react/react-source/packages/react-reconciler/src/ReactFiberConcurrentUpdates.ts:78) `finishQueueingConcurrentUpdates`、[ReactFiberWorkLoop.ts:466](/Users/wangcheng/Documents/workSpace/frontEnd/referenceProjects/repos/react/react-source/packages/react-reconciler/src/ReactFiberWorkLoop.ts:466) 剩余 lanes 计算。
- **官方对应**：采用四元组暂存队列时，应完整对应 [官方 ReactFiberConcurrentUpdates.new.js:45](https://github.com/facebook/react/blob/v18.3.1/packages/react-reconciler/src/ReactFiberConcurrentUpdates.new.js#L45) 的 `concurrentlyUpdatedLanes` / `getConcurrentlyUpdatedLanes`，以及 [官方 ReactFiberWorkLoop.new.js:2065](https://github.com/facebook/react/blob/v18.3.1/packages/react-reconciler/src/ReactFiberWorkLoop.new.js#L2065) 的提交合并。npm old 另见 [官方 ReactFiberConcurrentUpdates.old.js:34](https://github.com/facebook/react/blob/v18.3.1/packages/react-reconciler/src/ReactFiberConcurrentUpdates.old.js#L34) 的 interleaved 协议。
- **根因**：本地延后冒泡祖先 childLanes，却没有保存并在 commit 合入暂存并发更新的 lanes；已经完成的祖先不会重新 bubble。`markRootFinished` 只信 finished tree 的 lanes，清掉仍有新更新的根标记。
- **影响与证据**：不是仅延迟显示，而是新队列项失去继续调度的依据。`concurrent-update-after-subtree-completes` 稳定复现；反映同版本不同 reconciler 协议只移植一半的问题。

### F03 · P1 · 挂起 Transition 后的同步更新使 Context 保留旧画面

- **触发**：memo Reader 读取 Provider 的值；Transition 从 0 更新到 1，在 Reader 后方挂起；随后 `flushSync` 更新到 2。
- **官方 / 本地**：官方 `{phase:"2", context:"2"}`；本地外层 phase 已是 `"2"`，Reader 仍显示 `"0"`。
- **本地位置**：[ReactFiberNewContext.ts:76](/Users/wangcheng/Documents/workSpace/frontEnd/referenceProjects/repos/react/react-source/packages/react-reconciler/src/ReactFiberNewContext.ts:76)，特别是第 87 行；后续函数组件 bailout 见 [ReactFiberBeginWork.ts:269](/Users/wangcheng/Documents/workSpace/frontEnd/referenceProjects/repos/react/react-source/packages/react-reconciler/src/ReactFiberBeginWork.ts:269)。
- **官方对应**：[官方 ReactFiberNewContext.old.js:625](https://github.com/facebook/react/blob/v18.3.1/packages/react-reconciler/src/ReactFiberNewContext.old.js#L625) `prepareToReadContext`，第 641 行使用 `includesSomeLane`。
- **根因**：本地用 `isSubsetOfLanes(renderLanes, dependencies.lanes)` 要求包含整个依赖 lane 集合；当依赖累积不同优先级时，当前渲染只要命中其中一条就应视为收到更新。本地未正确设置 `didReceiveUpdate`，使消费结果被 bailout。
- **影响与证据**：同一页面提交不一致值，不能归为 Context 栈的外围简化。`context-after-suspended-transition`。上一轮 Provider unwind 修复解决的是另一层问题。

### F04 · P1 · 内层 Suspense 的 fallback 再挂起时反复捕获自身

- **触发**：内层 primary 抛未决 Promise，内层 fallback 也抛未决 Promise；外层有可正常显示的 fallback。
- **官方 / 本地**：官方显示 `"outer"`；本地同步 render 不返回，子进程 5 秒超时。
- **本地位置**：[ReactFiberThrow.ts:83](/Users/wangcheng/Documents/workSpace/frontEnd/referenceProjects/repos/react/react-source/packages/react-reconciler/src/ReactFiberThrow.ts:83) `getNearestSuspenseBoundaryToCapture`，第 88 行只检查 `ShouldCapture`。
- **官方对应**：[官方 ReactFiberThrow.old.js:272](https://github.com/facebook/react/blob/v18.3.1/packages/react-reconciler/src/ReactFiberThrow.old.js#L272) 会调用 [官方 ReactFiberSuspenseComponent.old.js:70](https://github.com/facebook/react/blob/v18.3.1/packages/react-reconciler/src/ReactFiberSuspenseComponent.old.js#L70) `shouldCaptureSuspense`，跳过已处于 fallback 的边界。
- **根因**：unwind 后捕获状态已改变，仅检查 `ShouldCapture` 不能判断边界是否正在展示 fallback，导致同一个边界再次被选中。
- **影响与证据**：普通嵌套加载占位即可阻塞渲染，应交给外层处理的恢复路径失效。`nested-suspending-fallback`；源码与超时 checkpoint 相互支持，不把超时单独当成无限循环的全部证明。

- **触发**：内层边界捕获 primary 错误后，其 fallback 自身又抛错；外层有正常 fallback。
